# Clue Protocol: Contracts

Smart contracts for the **Clue Protocol** (Crypto Identification Secure Protocol, CISP): an identity layer for digital finance anchored on an EVM Layer 2.

The repository holds two layers: the deployable **ClueCode** NFT contract, and the abstract building blocks that will be assembled into **ClueRegistry**.

> Reference implementation. **Not audited.** Do not deploy to mainnet before an independent audit.

- Node.js 18+ and npm
- GNU Make
- Go 1.25+ for the integration tests
- Optional: [`abigen`](https://geth.ethereum.org/docs/tools/abigen) from go-ethereum, to generate Go bindings

## Build

```sh
make init       # npm install, create out/ directories
make compile    # compile Solidity, generate typechain types, export out/abi + out/bin
make bindings   # additionally generate out/go/code/ClueCode.go (requires abigen)
```

| Target | What it does |
| --- | --- |
| `make init` | Installs npm dependencies and creates `out/abi` and `out/bin` |
| `make compile` | Runs `hardhat compile` and then `make abi` (TypeScript typechain types are generated by Hardhat) |
| `make abi` | Re-exports `out/abi/ClueCode.abi` and `out/bin/ClueCode.bin` from existing artifacts |
| `make bindings` / `make go` | Depends on `compile`, then runs `abigen` into `out/go/code/ClueCode.go`; fails if `abigen` is missing |
| `make test` | Runs `npx hardhat test` (currently 0 tests — see [Testing](#testing)) |
| `make clean` | Removes Hardhat artifacts, cache and `out/` |
| `make clean-abi` / `clean-bin` / `clean-bindings` | Removes `out/abi`, `out/bin`, or `out/go` |
| `make clean-all` | `clean` plus `node_modules` |
| `make refresh` | Runs `go mod tidy` and refreshes `tests/deploy` with `drag` |
| `make help` | Default target; lists the above |

`make compile` does **not** run `abigen`; use `make bindings` for the Go package. Set `EVM_VERSION` (default `paris`) to match the target L2, e.g. `EVM_VERSION=cancun make compile`.

## Testing

There are currently no Hardhat/TypeScript tests, so `make test` and `npm test` report `0 passing`. The real suite is Go integration tests in `tests/`:

```sh
go test ./tests/...
```

`TestDeploy` needs a funded key and `DEPLOY_RPC_URL` in `tests/.env`; it skips when the variable is unset. The operational tests in `code_operational_test.go` read the deployment JSON written by `TestDeploy`, so run `TestDeploy` first with `DEPLOY_OUT_FILE` set. `tests/.env` is gitignored and holds a local development key only — never commit a real private key.

## Go bindings

The generated package lives in `out/go/code`. With the module path `github.com/clue-protocol/contract`:

```go
import "github.com/clue-protocol/contract/out/go/code"

c, err := code.NewClueCode(address, client) // client: *ethclient.Client
grade, err := c.GradeOf(nil, big.NewInt(27))
canon, err := c.Canonical(nil, big.NewInt(2)) // "02"
```

Regenerate after a contract change with `make bindings`.

## Architecture

### ClueCode

ERC-721 ownership of a **Provider Code** — the numeric prefix of a Clue ID (for example `27` in `27-1234567890`). Grade is derived from digit length and the canonical form is the zero-padded decimal string shared by Solidity, Go and TypeScript.

| Grade | Digits | Range | Supply |
| --- | --- | --- | --- |
| S | 2 | 01–99 | 99 |
| A | 3 | 100–999 | 900 |
| B | 5 | 10000–99999 | 90,000 |

Total supply is **90,999**. Zero, four-digit codes and anything above `99999` are invalid.

Beyond standard ERC-721, ClueCode exposes:

- `gradeOf`, `isValidCode`, `canonical`, `isMinted`, `totalMinted`, `MAX_SUPPLY`
- `mint`, `mintBatch`, `mintWithMetadata` (`MINTER_ROLE`)
- `setMetadata`, `setMetadataBatch`, `clearMetadata`, `setBaseURI`, `freezeCode`, `freezeMetadata` (`METADATA_ROLE`)
- `metadata`, `metadataOf`, `hasMetadata`, `tokenURI`, `supportsInterface` (includes ERC-4906)

Constructor: `ClueCode(address admin, uint48 adminDelay, address minter, string initialURI)`. Metadata is stored per token; `tokenURI` uses `baseURI + canonical(code)` for codes without stored metadata, otherwise an on-chain base64 JSON document. `METADATA_ROLE` is granted to the admin at deployment.

See [`src/code/README.md`](src/code/README.md) for the token model and test vectors.

### Registry building blocks

- **`ClueCodeControl`** — per-code role storage. `CONTROLLER_ROLE` marks the depositor and is managed only by the vault lifecycle. All its functions are `internal`; inheriting contracts decide what to expose.
- **`ClueCodeVault`** — holds the ClueCode token. `activateCode` (internal) pulls an approved token and assigns the controller/admin; `releaseCode` (external) returns it only while the code is Stateless. Status moves `Open → Stateless → Active` via internal `_lock`/`_unlock`. Includes a reentrancy guard and strict ERC-721 receiver checks.
- **`ClueProvider`** — per-code configuration and capacity. Static codes record a network/token target; Route codes delegate to a Profile Server key. Links carry a Domain or Alloc partition, and direct/linked Clue ID counts are enforced against grade-based ceilings.
- **`ClueValidators`** — global validator registry. The `Authorizer` is initially the deployer and can be handed over with the internal `transferAuthorizer` (exposed by the concrete registry); it registers validators with `registerValidator` and removes them with `resolveValidator`, which only succeeds when `validatorLinkCount` is zero. Code controllers link and unlink validators with `linkValidator`/`unlinkValidator`; `isValidatorLinked` and `linkedValidatorsOf` are the corresponding views, and `listValidators` enumerates the global registry.

The components share `ClueCodeControl` through inheritance; the concrete `ClueRegistry` that combines them is still to be written.

## Deployment

ClueCode is deployed with four constructor arguments: admin (ideally a multisig), admin delay in seconds, genesis minter, and an initial fallback base URI.

```sh
ADMIN=0x… MINTER=0x… ADMIN_DELAY=86400 INITIAL_URI=https://… \
  npx hardhat run scripts/deploy.ts --network <network>
```

> `scripts/deploy.ts` has not yet been updated for the four-argument constructor — it currently passes only `(admin, delay, minter)`. Pass the initial URI explicitly (or update the script) before deploying.

Genesis minting is available once ClueCode is deployed:

```sh
CLUECODE=0x… BATCH=250 DISTRIBUTOR=0x… RENOUNCE_MINTER=1 \
  npx hardhat run scripts/genesis.ts --network <network>
```

`genesis.ts` mints all 90,999 codes, verifies `totalMinted()` and a few canonical forms, and optionally renounces `MINTER_ROLE`. Benchmark `BATCH` against the target L2's block gas limit. The admin lock-down (delayed default-admin renounce) remains a separate multisig step. Define networks and keys locally; never commit private keys.

## Design principles

- **Ownership is an on-chain asset.** A Provider Code is a token, not a permission granted by the Foundation.
- **Componentized registry.** Custody, control, provider configuration and validators are separate abstract modules, assembled by one concrete registry.
- **Metadata is configurable but lockable.** Roles can set per-code metadata, then freeze a single code or all metadata permanently.
- **No silent key transfer.** Owning a code gives no signing authority; Profile Server and validator keys are registered in the registry modules.
- **One canonical form.** Every code has exactly one decimal representation shared by Solidity, Go and TypeScript.
- **No proxies.** Contracts are intended to be immutable once deployed.

## Known gaps

- `ClueRegistry.sol` and `ClueMultiSig.sol` are empty placeholders; none of the registry modules is deployable yet.
- `scripts/deploy.ts` still uses the old three-argument ClueCode constructor.
